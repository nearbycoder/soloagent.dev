Durable AI agents for the places your team already works

soloagent runs agents on your existing Claude, ChatGPT, or GitHub Copilot subscription, or on any API key. It connects them to Slack, Discord, Telegram, webhooks, a web dashboard, and a terminal. It's built on Pi Durable, so every step is persisted and interrupted runs resume where they stopped.

Work that survives restarts

soloagent is built on Pi Durable. Every model turn, tool call, delegation, and reminder is a durable step stored in SQLite. If the process stops mid-answer during a deploy, a crash, or a container restart, the next start resumes the run from its last checkpoint.

Commit before show
Nothing reaches Slack or the dashboard until it has been written to storage.
Resume, not restart
An interrupted model request is retried. Finished tool calls are never run twice.
Durable timers
A reminder set for Friday sleeps in storage and fires on Friday, across any number of deploys.

How credentials are handled

Tokens and keys are encrypted at rest with AES-256-GCM using a secret you control. OAuth tokens refresh automatically and are never sent to the browser. A built-in demo model lets you try everything before connecting an account.

Routing that reads like chat

Start a message with @coder or coder: to address an agent. Otherwise the connector's assigned agent answers. A message sent while an agent is working steers the current run instead of waiting in a queue.

#eng-deploys
maya   @coder why did last night's deploy fail?
maya   actually, only check the API service ← steers the run
sam    scout: what changed in Postgres 17.2?
sam    !agents   !reset   !stop   !help

Web dashboard and terminal UI

Both talk to the same server over the same API. Manage agents, sign-ins, and connections in the browser. Stay on the keyboard with the terminal UI, which runs its own local server when you're not connected to one.

Agents with skills, not just prompts

Give each agent a name, a handle, instructions, a model, and the skills it needs. Skills are Pi Durable extensions, so their work is persisted like everything else.

memory
Remembers people, preferences, and decisions across conversations, with recall and forget.
web
Fetches pages and APIs as readable text and searches the web.
delegate
Hands a task to another agent through a durable child conversation and waits for the answer.
schedule
Sets reminders and follow-ups that sleep in storage and fire after any number of restarts.
workspace
Reads, writes, and edits files and runs shell commands in a private folder. Off by default.

Scriptable from end to end

Everything the dashboard and terminal do goes through a documented HTTP and WebSocket API. Use the typed TypeScript client, call it from CI, or embed the runtime in your own service.

  • REST for agents, threads, providers, connectors, and schedules
  • WebSocket stream of messages, partial answers, and tool progress
  • Bearer-token auth; one admin token per deployment

# Ask once and print the answer
soloagent ask "Summarize today's incidents" --agent ops

# Pipe anything in
git diff --staged | soloagent ask - --agent coder

# Use a remote server from now on
soloagent connect https://solo.example.com \
    --token $SOLOAGENT_TOKEN
import { SoloClient } from "@soloagent/client";

const solo = new SoloClient({
  baseUrl: "https://solo.example.com",
  token: process.env.SOLOAGENT_TOKEN,
});

const thread = await solo.createThread({ agentId: "coder" });
const { answer } = await solo.ask(thread.id, "Why did CI fail?");

// Stream partial answers and tool progress
const stream = solo.connect();
stream.subscribe(thread.id);
# From any system that can send a request
curl -X POST https://solo.example.com/api/hooks/$HOOK_ID \
  -H "x-solo-secret: $HOOK_SECRET" \
  -H "content-type: application/json" \
  -d '{"text": "@coder what changed in the last deploy?",
       "thread": "deploys", "user": "ci"}'

# → {"thread":"deploys","status":"done","answer":"…"}

Runs on your infrastructure

soloagent is a single Node.js service with a single data directory. Deploy it to Railway in a few minutes, or run it anywhere with Docker or Node 22.19+.

  1. Deploy

    Create a Railway service from the repository and attach a volume at /data. The included Dockerfile does the rest.

  2. Configure

    Set SOLOAGENT_TOKEN for access and SOLOAGENT_SECRET to encrypt credentials, then open your domain.

  3. Connect

    Sign in to a model provider, create agents, and add Slack, Discord, or Telegram from the Connections page.

Or run it locally

The terminal UI starts an embedded server with its data in ~/.soloagent. The web dashboard is available with soloagent serve.

git clone https://github.com/nearbycoder/soloagent.dev
cd soloagent.dev
npm install && npm link -w @soloagent/cli
soloagent

Questions

Is it free?
Yes. soloagent is MIT-licensed and self-hosted. You pay your model provider and your host, nothing else.
Can I really use my Claude or ChatGPT subscription?
Yes, through the same OAuth sign-in flows Pi uses. Check each provider's terms; Anthropic, for example, bills third-party usage as extra usage rather than against plan limits.
What happens if the server restarts mid-answer?
The run resumes from its last committed step. Completed tool calls are not repeated, and an interrupted model request is retried.
Do I need a public URL for Slack?
No. Slack uses Socket Mode, and Discord and Telegram connect outbound as well. You need a domain only for the dashboard, webhooks, and remote terminal access.
Where is my data stored?
In two SQLite databases in your data directory: Pi Durable's conversation store and soloagent's own metadata. Nothing is sent anywhere except to the model providers you configure.
What is Pi?
Pi is Earendil's open-source agent toolkit. soloagent uses pi-ai for model access, pi-durable for durable execution, and pi-tui for the terminal UI.
